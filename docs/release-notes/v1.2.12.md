# CPAMP Mobile 1.2.12

这一版本将凭证额度切换为 Manager Server 标准巡检结果，并改进请求监控、暗色模式、无障碍布局和更新安全性。

## 中文

### 🔑 服务端凭证额度

- 凭证额度现在直接读取 Manager Server 最新完成的 CPAMP 巡检，不再由手机查询提供商接口。
- 显示巡检来源、完成时间和运行编号，并区分无结果、网络、认证、限流、旧版服务端和服务端结果错误。
- 额度页面改为按需加载，并使用按服务器隔离、移除账号标识的隐私缓存。
- 额度状态拥有独立 ViewModel，不再与流量监控共享加载生命周期。

### 📊 监控与界面

- 请求监控新增首字耗时（TTFT），便于区分首包响应和完整请求延迟。
- 指标卡、请求事件、凭证名称和底部导航改进大字体与窄屏换行表现。
- OpenAI 和 xAI 单色图标现在会跟随主题前景色，在暗色模式下保持清晰可见。
- 更新 README 快速开始、当前架构和安全边界说明。

### 🔐 安全与可靠性

- 管理请求继续禁止重定向，避免 Admin Key 被转发到其他地址。
- 应用更新允许 GitHub 的 HTTPS 重定向，但拒绝 HTTPS 到 HTTP 的协议降级。
- 保持固定发布路径、SHA-256、应用包名和签名证书的多层更新校验。
- 修复凭证额度缓存清理函数的 Kotlin 作用域问题。

## English

This release moves credential quotas to standardized Manager Server inspection results and improves request monitoring, dark mode, accessibility layouts, and update security.

### 🔑 Server-side credential quotas

- Credential quotas now read the latest completed CPAMP inspection from the Manager Server instead of querying provider APIs from the phone.
- The quota screen shows the inspection source, completion time, and run ID while distinguishing missing results, network, authentication, rate-limit, old-server, and server-result failures.
- Quotas load on demand and can reuse a profile-isolated privacy cache with account identifiers removed.
- Quota state now has a dedicated ViewModel and no longer shares its loading lifecycle with traffic monitoring.

### 📊 Monitoring and interface

- Request monitoring now includes time to first token (TTFT) alongside total request latency.
- Metric cards, request events, credential names, and bottom navigation handle large text and narrow screens more reliably.
- Monochrome OpenAI and xAI marks now follow the theme foreground color for clear dark-mode contrast.
- Updated the README quick start, current architecture, and security boundaries.

### 🔐 Security and reliability

- Management requests continue to block redirects so the Admin Key cannot be forwarded to another address.
- In-app updates allow GitHub HTTPS redirects while rejecting HTTPS-to-HTTP protocol downgrades.
- Update verification still requires the fixed release path, SHA-256, application package, and installed signing identity.
- Fixed the Kotlin scope of the credential quota cache sanitizer.
